# Kebloop for Linux — architecture

A native Linux port of Kebloop written in Rust. It mirrors the macOS app's
behaviour (see `../docs/usage.md`, `../docs/automation.md`, `../docs/conversions.md`)
and maps each macOS mechanism to its Linux equivalent. The Swift sources in
`../Sources` are the reference implementation; the Swift tests in `../Tests` are
the reference test-suite and are ported to Rust wherever the behaviour is
platform-neutral.

## Workspace layout

| Crate | Role | Depends on |
| --- | --- | --- |
| `kebloop-core` | Pure engines: calculator, unit/duration conversion, date and relative-date calculation, time zones, currency conversion from saved rates, app-search ranking, Unicode emoji catalog, AI prompt URLs. No I/O. Port of `Sources/KebloopCore`. | — |
| `kebloop-services` | Platform-neutral app logic with persistence: configuration/profiles/import-export, quicklinks, aliases, snippets (defaults, dynamic values, keywords), personalization (launch counts, pins, recents), clipboard history store, calculator history, exchange-rate cache and refresh, file-search exclusions and ranking, command registry, window-management and result-action models, script commands and the v1 extension protocol, localization catalogs. No GTK. | core |
| `kebloop-platform` | Linux integration, no GTK widgets: XDG `.desktop` application index, file indexer, Wayland clipboard watcher, logind power-off, XDG autostart, global shortcuts (portal), single-instance IPC, tray (StatusNotifierItem). | core, services |
| `kebloop` | GTK4 + libadwaita + gtk4-layer-shell binary: launcher panel, action menu, emoji grid, clipboard/quicklink/snippet/script/extension views, settings, help, onboarding; CLI. | all |

Rules:

- Engines and stores are synchronous, deterministic and unit-tested. Time, paths
  and environment are injected (e.g. `now: SystemTime`, `base_dir: &Path`) so
  tests never touch the real home directory.
- Blocking work (indexing, subprocesses, D-Bus) runs off the GTK main thread;
  results come back through `async-channel` / `glib::MainContext::spawn_local`.
- Errors are typed (`thiserror`) in libraries; `anyhow` only in the binary.
- No `unwrap()`/`expect()` on user data, files, or IPC. Panics are bugs.
- `cargo clippy --workspace --all-targets -- -D warnings` and `cargo fmt --check` must pass.

## macOS → Linux mapping

| macOS | Linux |
| --- | --- |
| Option-Space via Carbon hotkey | Single-instance `GtkApplication` (D-Bus id `io.github.kubamus.Kebloop`). `kebloop toggle` toggles the launcher from any compositor keybinding. Additionally registers the XDG **GlobalShortcuts portal** (KDE, GNOME 48+, Hyprland) when available. Default suggested binding: Alt+Space. |
| App / command shortcuts | Same mechanism: portal shortcuts when available; always also exposed as `kebloop launch <desktop-id>` and `kebloop command <id>` for compositor bindings. Settings shows ready-to-paste snippets for niri, Hyprland, Sway, i3. |
| NSPanel + Liquid Glass | gtk4-layer-shell overlay surface (wlroots, niri, Hyprland, KDE), exclusive keyboard while shown (on-demand while one of Kebloop's own confirmation dialogs or the action popover is open, so they receive keys; focus loss still hides the panel whenever the compositor reports it), top-centered on the output the surface actually entered (the top margin is recomputed from the `enter-monitor` event; a configured fixed output is looked up again on every show and falls back to the focused output when disconnected). Fallback: undecorated `GtkWindow` (GNOME/X11). Translucency via CSS + compositor blur. |
| `/Applications` scan, NSWorkspace launch | XDG `applications/` dirs from `$XDG_DATA_HOME` + `$XDG_DATA_DIRS` (incl. Flatpak/Snap exports), desktop-entry spec precedence and `NoDisplay`/`Hidden`/`OnlyShowIn`/`TryExec` rules, `Actions` exposed as result actions. Launch with `gio::DesktopAppInfo` (handles `Terminal=true`, field codes, Flatpak). Icons from the GTK icon theme. Cache in `$XDG_CACHE_HOME/kebloop/application-index.json`. inotify watch + 5-minute rescan. |
| Spotlight file search | In-process index of the folders chosen in Settings (default: XDG user dirs), built with the `ignore` crate (respects `.gitignore`, nested rules, negations, global excludes, `.git/info/exclude`, but only inside git repositories: a stray `.gitignore` elsewhere hides nothing) plus the built-in exclusions. When the entry cap truncates the walk it is redone single-threaded in sorted order so the result is identical on every rebuild. Rebuilt in the background on settings changes and every 30 minutes; queries are in-memory, debounced 35 ms, max 40 results, 12 shown in root search. |
| NSPasteboard polling | Wayland `ext-data-control-v1` / `zwlr-data-control-unstable-v1` (niri, Sway, Hyprland, KDE) to watch and set the clipboard without focus. X11 uses XFixes selection notifications and bounded selection/INCR transfers. GNOME Wayland uses the optional Shell extension and separately polls revision metadata and bounded cached multi-format data. Sensitive markers: `x-kde-passwordManagerHint: secret`, `application/x-nspasteboard-concealed-type`. X11 owner identities can be excluded; source-app exclusion is not available on native Wayland (documented). The Wayland thread never blocks on a source: pipes are handed to a reader thread, so writes (`set_clipboard_async`, fire-and-forget; the UI falls back to the GDK clipboard if the thread reports a failure) are never delayed. A shared recording flag (history enabled and not paused, kept current by the app) stops the watcher from reading any content while history is off; with a secret marker present only the marker values are read. Offered mime types are canonicalised (`kebloop_services::clipboard::canonical_mime`: lower case, no spaces, `charset=utf-8` normalised, `UTF8_STRING`/`STRING`/`TEXT`/`text/plain` variants all become `text/plain;charset=utf-8`) and the store looks formats up the same way. Text above 100 KB is dropped; a bounded rich-text or image payload alongside it is still kept, as on macOS. |
| Direct paste via Accessibility (Clipboard, Emoji, snippet Insert) | Copy, hide the launcher, then `kebloop_platform::paste::paste_into` uses native XTEST on X11, native virtual input through the GNOME extension, or types Ctrl+V (Ctrl+Shift+V for terminal app ids) with `wtype`/`ydotool` into the window that was focused when the launcher was shown (captured by a worker via the compositor IPC). Paste is cancelled when the focused window or the clipboard revision changed. One `directPasteEnabled` flag (default on when a tool is installed; legacy `snippetPasteEnabled` still read, new key written). Without a tool the result is copy-only with an "install wtype" hint. Logic is GTK-free in `direct_paste.rs`. |
| Shutdown confirmation | Kebloop's own confirmation dialog, then `org.freedesktop.login1.Manager.PowerOff(interactive=true)` over D-Bus (zbus). |
| Launch at login (SMAppService) | `$XDG_CONFIG_HOME/autostart/io.github.kubamus.Kebloop.desktop`. `Exec` uses desktop-entry quoting (double quotes, escaped `"`, `` ` ``, `$`, `\`; `%` doubled) and the absolute path of the running binary unless it is installed in `/usr/bin`, `/usr/local/bin`, `/bin` or `/usr/sbin`. |
| Menu-bar icon | StatusNotifierItem tray (`ksni`), optional; the app works without a tray. It is registered with `assume_sni_available`, so starting before the panel/watcher exists is fine: the icon appears when a watcher comes online. |
| UserDefaults | `$XDG_CONFIG_HOME/kebloop/config.json` (atomic write that follows a symlinked file, same portable export schema as macOS so exports are cross-compatible where meaningful). |
| Application Support | `$XDG_DATA_HOME/kebloop/` (clipboard history + attachments, mode 0600/0700). |
| Apple Shortcuts | Not available on Linux; the command is hidden. Imported macOS configuration keeps those entries but reports them as unavailable. |
| Currency rates (`CurrencyRateStore`, UserDefaults cache) | `kebloop_services::currency`: blocking `ureq` + rustls from a worker thread (never the GTK thread), injected `RateFetcher` for tests, same source (Frankfurter `GET /v2/rate/{from}/{to}`) and cache policy (24 h freshness, 30 s retry delay, 30 days retention, 64 pairs, 32 KiB responses). Cache file in `$XDG_CACHE_HOME/kebloop/currency-rates.json`; offline conversions work from it and are marked `cached` when stale. The GTK app refreshes a query's pair on a worker thread (`services/rates.rs`) and re-evaluates when the rates change. The engine in `kebloop-core` only receives `CurrencyRateSnapshot`s. |
| Emoji data | `Sources/KebloopCore/Resources/emoji-test.txt` is embedded with `include_str!` and parsed lazily on first use (about 2 ms) into 3,963 entries on top of the curated names and aliases. The Unicode License V3 text is embedded too (`EmojiCatalog::UNICODE_LICENSE`) and installed by the package. |
| Calculator history (UserDefaults) | `$XDG_DATA_HOME/kebloop/calculation-history.json` (owner-only, 100 entries); not part of the portable configuration, so never exported or imported. Recorded when a calculator result is copied (never while typing); browsed with the Calculator History command (Return copies, Ctrl+K clears with confirmation). |
| Snippet keyword expansion (CGEvent tap) | Opt-in AT-SPI TextChanged/EditableText service on X11 and Wayland. Only focused, editable, unselected non-password text is read, bounded to 128 characters; replacements are limited to 4,096 characters. Applications without accessible editable text remain unsupported. |
| System commands (AppleScript) | `kebloop_platform::system_actions`: logind D-Bus with `loginctl` fallback (lock, sleep, restart, log out), `wpctl`/`pactl` (mute), appearance portal/`gsettings` (appearance). Availability is probed on a worker thread (`services::system`), exposed as `CommandAvailability` (`platform.rs`) and hides commands whose backend is missing. Restart and Log Out use `confirm` in `launcher/control.rs`; failures are shown in a notification. `KEBLOOP_DRY_RUN_SYSTEM_ACTIONS=<file>` logs instead of acting. |
| Window management (Accessibility) | `kebloop_platform::window_management` over the compositor IPC (niri, Sway, i3, Hyprland), EWMH on X11, native KWin scripting on Plasma 6 and the optional GNOME Shell bridge; per-action support (`Full`/`Approximate`/`FloatingOnly`/`Unsupported`) decides whether a command is listed and which note the row shows. Commands act on the window focused before the launcher (`launcher/control.rs`), or on the focused window when run from a shortcut or `kebloop command <id>`. Settings → Window Management records shortcuts and shows the compositor snippets. |
| Running-app controls (NSRunningApplication) | `AppIdentity` (desktop id, `StartupWMClass`, `Exec` basename) matched against compositor windows (`kebloop_platform::app_control`); Hide where the compositor can park windows, Quit by closing windows, Force Quit by pid after confirmation, Restart = quit and relaunch. The app shortcut toggle uses `plan_toggle_focus` + `AppController`. |
| Pinned favorite indicator | `view-pin-symbolic` per result row (tooltip "Pinned to Favorites", hidden from the accessibility tree) and an accessibility label on the row. |
| Siri AI handoff | Not available; providers are ChatGPT and Claude (prompt URLs opened with the default browser). A stored `siri` provider falls back to ChatGPT. |
| Localizable.strings (en, pl) | The same `../Sources/Kebloop/Resources/*.lproj/Localizable.strings` catalogs are embedded at build time (`include_str!`) and parsed at startup, plus `resources/*.strings` for Linux-only keys. Language from `LANGUAGE`/`LC_ALL`/`LC_MESSAGES`/`LANG`. |
| Script commands / extensions | Same v1 JSON protocol and limits. Subprocess in its own process group (`setsid`/`process_group(0)`), `killpg` on cancel/timeout and, synchronously (SIGTERM, 300 ms, SIGKILL), for every running group on quit. Environment: `env_clear` plus `PATH=/usr/local/bin:/usr/bin:/bin`, `LANG=C.UTF-8` and the non-secret session variables `HOME`, `XDG_RUNTIME_DIR`, `WAYLAND_DISPLAY`, `DISPLAY`, `DBUS_SESSION_BUS_ADDRESS`, `XDG_CURRENT_DESKTOP` (so `notify-send`, `wl-copy`, `playerctl` work; macOS passes only PATH and LANG). |

## Storage paths

- Config: `$XDG_CONFIG_HOME/kebloop/config.json`
- Clipboard: `$XDG_DATA_HOME/kebloop/clipboard-history.json`, attachments in `$XDG_DATA_HOME/kebloop/clipboard-attachments/`
- Calculator history: `$XDG_DATA_HOME/kebloop/calculation-history.json`
- Cache: `$XDG_CACHE_HOME/kebloop/` (application index, `currency-rates.json`)

## Persistence, startup problems and shutdown

- Atomic writes (`util::atomic_write`: temporary sibling, fsync, rename, directory fsync) resolve a symlinked target first, so a dotfiles-managed config stays a link.
- Frequent saves are debounced by `kebloop_services::persist::DebouncedWriter`: the clipboard history file and the usage counters (launch counts, recents, emoji recents) are written by one worker thread about 500 ms after the last change (at most 3 s later under continuous changes) instead of rewriting and fsyncing on the GTK thread for every copy or launch. A launch is one save, not two. All writes of a process go through one lock and the data is taken only after the lock is held, so there are never two concurrent writers of a file and an older snapshot never overwrites a newer one. Settings edits stay synchronous (and discard older pending data). `app::shut_down_services` (also run on `GApplication::shutdown`, `SIGTERM` and `SIGINT`) cancels runs, terminates their process groups and flushes pending writes.
- The launcher starts even when a store cannot be opened. `ConfigStore::in_memory` runs with defaults and never writes (so a configuration written by a newer Kebloop is not clobbered); `ClipboardStore::unavailable` turns history off. The reason is shown in Help ("Startup notices"), in Settings → Clipboard and as a desktop notification. Moving a corrupt configuration or history file aside (`*.corrupt`) is announced the same way; a recovered configuration is not a first run, so clipboard recording is left as it was.
- Existence of pinned files is answered from a cache refreshed by a worker thread (the GTK thread never `stat`s them); clipboard filtering matches the whole text of each entry using a per-entry folded-text cache; thumbnails are keyed by entry id and attachment file name, and images whose header claims more than 16384 px per side or 40 megapixels are not decoded.
