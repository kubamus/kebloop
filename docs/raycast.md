# Raycast migration and compatibility

Use **Import Raycast Export** to preview JSON produced by Raycast's **Export Snippets** and **Export Quicklinks** commands. Select categories and individual valid items before importing. Existing names, identical contents and quicklink keyword conflicts are skipped; existing Kebloop configuration is never replaced. Imports are additive and become part of Kebloop's normal configuration exports.

Supported snippets use `name`, `text`, and optional `keyword` fields. Keywords are deliberately omitted on import so even an already-enabled typing monitor cannot activate new triggers. Add reviewed triggers manually afterward. Snippets containing braces that look like dynamic placeholders are rejected because Raycast's grammar differs from Kebloop's. Quicklinks support `name`, `link` (or `url`) and optional `keyword`; destinations must match Kebloop's HTTP(S), absolute file path or `{query}` URL template rules. Raycast placeholders other than `{query}` require conversion first. Tags, icons and rich formatting are not imported.

Encrypted `.rayconfig` backups are not supported. Raycast's current export documentation describes encrypted full backups; Kebloop does not guess the format, request a passphrase, or read Raycast's keychain. Other categories, including aliases and hotkeys, remain pending.

## Script Command compatibility

**Raycast Compatible Commands** reads actual `@raycast` comment metadata from a selected script. It accepts schema version 1, macOS scripts with an absolute shebang interpreter, and `silent`, `compact` or `fullOutput` modes. The original script remains unchanged. A positional-argument shell wrapper sets the working directory to the script's directory, then executes the original shebang interpreter with its flags and script path. Source paths are passed as arguments rather than interpolated into shell code. The existing Kebloop script runner supplies cancellation, timeout and bounded plain text output; output from all supported modes is visible there rather than reproducing Raycast toast/UI presentation.

Import does not execute the script and always installs it disabled. Review its source with the provided button and enable it explicitly in Script Commands. Dependencies and interpreters must already be installed. The runner passes only a fixed system `PATH` and UTF-8 locale, without inherited environment variables or credentials; `/usr/bin/env` shebangs cannot find Homebrew runtimes unless adapted to an absolute interpreter path. Scripts relying on `$HOME` or environment-provided credentials must be adapted explicitly. Scripts have ordinary user access and can access network services; any API credentials and third-party service charges are the user's responsibility. Kebloop neither transfers Raycast credentials nor buys Raycast AI services.

Rejected metadata includes argument forms (including password/dropdown inputs), inline refresh, custom `currentDirectoryPath`, non-macOS platform and `needsConfirmation true`. No background scheduler is created. Icons, package names and author metadata are informational and do not affect execution.

## JavaScript extension SDK subset

The compatibility panel also runs real standalone compiled JavaScript **no-view** commands that import `@raycast/api` unchanged. Select the original Raycast `package.json`, command name, compiled `.js`/`.mjs` entry and an installed Node or Bun executable. Validation previews the command and imports it disabled; review the source, fill preferences, explicitly enable it, then Run. No package manager, dependency installation or source compilation happens automatically.

An isolated temporary module directory contains a small ESM `@raycast/api` implementation. The command's original bytes are copied there unchanged. Supported exports are plain-text `Clipboard.copy`, `getPreferenceValues` for textfield/textarea preferences, `showToast`/`showHUD` for static feedback, `Toast.Style`, and `open` for HTTP(S) URLs. A structured response validates the whole effects batch before native clipboard/URL operations occur. Feedback appears in the compatibility panel; mutable Toasts, actions and Raycast HUD placement are not reproduced. Unsupported imports/APIs produce an explicit failure and native effects are discarded. Code itself runs with normal account access and can still directly access the filesystem/network through JavaScript; this bridge is not a sandbox.

The runtime passes a fixed system PATH and UTF-8 locale without inherited credentials. Required preferences must be filled. Password and other nontext preference types are rejected; enter no secrets in persisted text preferences. Third-party API credentials and charges remain the user's responsibility. No Raycast credentials are read or migrated. Extension registrations and nonsecret preferences are stored locally in their own UserDefaults key and are not included in portable Kebloop configuration exports; source and runtime paths are specific to this Mac.

The executable examples in `examples/raycast-extension/` use unchanged SDK imports. `greeting.js` exercises preferences and clipboard feedback; `copy-uuid.js` copies a fresh UUID using Node’s built-in crypto module without external dependencies. React List/Form/Detail rendering, OAuth, Raycast AI, clipboard reads or paste, command argument forms, Store installation, TypeScript/JSX compilation, relative source modules and external package dependencies remain unsupported. Kebloop's own JSON extension protocol remains separate.
